# Repository hygiene and retention policy

Vibress is a self-hostable, upgradeable CMS. Never infer that a file is disposable simply because a TypeScript import search finds no consumers. External users may rely on public URLs, release assets, documented CLI commands, extension contracts, backups, migrations, and historical verification evidence.

## Source of truth and generated assets

- `graph.json` is generated by Nx and is ignored rather than committed.
- `scripts/media-storage-audit.json` is a local point-in-time inventory; aggregate findings are documented at [the historical media summary](../audits/media-storage-2026-09-19-summary.md).
- `content/theme-starter/` is the canonical starter theme source. `content/vibress-theme-starter.zip` is its existing distribution contract. Do not remove that stable path without a migration plan.
- `VIBRESS_THEME_DESIGNER_PACKAGE/starter-theme/` is a distinct designer example with independent source files. Do not replace it wholesale with `content/theme-starter/`.
- The designer distribution embeds `vibress-theme-starter.zip` from the canonical `content/` ZIP at packaging time. To regenerate the distributions in order:

```sh
node scripts/pack-starter-theme.js
node scripts/pack-theme-designer-package.js
```

The GitHub release workflow runs both commands and fails if either fails. `VIBRESS_THEME_DESIGNER_PACKAGE.zip` remains tracked for compatibility with existing raw-file consumers; a future change may retire that path only with a verified replacement and communication.

## Preserved contracts

- Keep released Drizzle SQL migrations and their metadata snapshots; upgrades must replay on a populated database.
- Keep public `/student.html` and `/theme-assets/student.html` aliases, theme CSS delivery URLs, `/rss.xml`, and `/feed.xml` until a separately tested compatibility redirect is in place.
- Keep both production smoke-test runners while the package command and deploy shell script invoke different formats.
- Keep `tests/e2e/baselines/` and Arabic/RTL design evidence. The formerly tracked `08-subscriptions-list-1440-dark.png` was an incorrectly labeled byte-for-byte copy of the genuine `09-settings-hub-1440-dark.png`; it was retired from active evidence. The existing `/admin/subscriptions` route serves the membership settings hub, **not** an independent subscriptions-list screen. See [design-evidence provenance](../design/screenshots/redesign/README.md); do not claim or fabricate an unavailable subscription-list capture.
- Keep all database backups, restore scripts, disaster-recovery drills, plugin SDK/public API contracts, and supported theme templates.

## Historical reports

The twelve former root-level Markdown reports are preserved verbatim in [the September 2026 archive](../archive/2026-09/README.md). Keep the historical SHA and conclusion intact. The [docs manifest](../manifest.json) carries its original curated count, not a live total; this is explicitly annotated to prevent mistaken deletion of later documentation.

## Change gate

For future cleanup: check `git status`, identify consumers (including workflows, Docker, reverse proxy, docs, themes, plugins, external URL contracts), make the smallest compatible edit, run focused tests, then verify `pnpm audit --prod --audit-level high`, `pnpm typecheck`, `pnpm lint`, `pnpm verify:explicit-any`, `pnpm vitest run`, `pnpm build`, and `pnpm verify:clean-tree`. Test fresh install and upgrade paths whenever deployment inputs change. Never run old workspace scaffolding scripts against the production monorepo.
