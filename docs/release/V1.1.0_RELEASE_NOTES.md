# Vibress v1.1.0

## Release Overview

**Vibress v1.1.0** is the first minor release following General Availability, introducing comprehensive multi-publication tenant isolation (Migration 0026), dedicated workspace domain orchestration, remote "What's New" in-app notifications, bundled trusted plugin registry, CRDT collaboration rate limiting and state exchange controls, 740px Studio reading measure redesign, and hardened Playwright E2E browser test coverage.

---

## Highlights

* **Multi-Publication Tenant Isolation (Migration 0026):** Complete foreign-key scoped tenant isolation across all domain repositories, protecting data boundaries across posts, pages, media, tags, themes, products, plans, billing, translations, automations, and newsletters.
* **Workspace Domain Service (`@vibress/workspaces`):** Dedicated domain package providing workspace context resolution, member role scoping, and multi-tenant boundary defense.
* **In-App "What's New" System:** Remote feed delivery subsystem with semver-aware audience targeting, client-side banner in Admin navigation, and user-level dismissal persistence.
* **Bundled Trusted Plugin Registry:** Deprecation of dynamic vm sandboxing in favor of explicit capability-scoped bundled plugin registration with prototype pollution defense.
* **CRDT Collaboration Controls:** 64KB message cap, Base64 validation, and rate limiting for real-time WebSocket collaborative editing sessions.
* **Studio Editorial Workspace:** 740px typography reading measure alignment, refined floating formatting toolbar, and synchronous Lexical state hydration from parsed JSON documents.

---

## Added

* **Multi-Publication Database Scoping:** Applied `publication_id` column constraints and foreign keys across all database tables via migration `0026_multi_publication_tenant_isolation.sql`.
* **Workspace Domain Service:** Implemented `packages/domains/workspaces` with `DrizzleWorkspaceRepository`, `DrizzlePublicationRepository`, and `WorkspaceService`.
* **"What's New" Notification Subsystem:** Added `@vibress/utils` semver and feed selector helpers, `@vibress/api-contracts` schema, and `WhatsNewService` with memory caching and user dismiss tracking.
* **Bundled Plugin Registry:** Added `packages/plugin-core/src/bundled-registry.ts` with capability verification and prototype security boundaries.
* **CRDT Rate Limiting & Sizing Guard:** Added `crdtRateLimiter` and 64KB frame size validation in `apps/api/src/routes/collaboration-ws.ts`.

---

## Changed

* **Studio Reading Canvas:** Aligned reading width to 740px measure for optimal editorial ergonomics.
* **Lexical Editor State Hydration:** Wired synchronous initial editor state parsing into `LexicalComposer` `initialConfig` in `@vibress/studio-react`.
* **Editor Component Keying:** Initialized `loading` state from `postId`/`pageId` in `PostEditor.tsx` and `PageEditor.tsx` to ensure clean hydration and prevent blank canvas on reload.
* **Security Dependencies:** Upgraded container base dependencies and `smol-toml` to resolve security audit findings.

---

## Fixed

* **Multilingual Browser QA Seeds:** Added `publicationId: "pub_default"` to direct database seed inserts in `tests/e2e/multilingual-browser-qa.test.ts`.
* **Dynamic Site Locale Resolution:** Fixed content resolution in API to dynamically resolve site locale settings instead of hardcoding `en`.
* **CI Docker Pulls:** Replaced Docker Hub image with `quay.io/minio/minio` in GitHub Actions CI to prevent unauthenticated pull rate-limiting.

---

## Security

* **Multi-Tenant Boundary Defense:** Enforced database-level and domain-level publication filtering preventing cross-tenant data leakage.
* **Plugin Capability Scoping:** Deprecated arbitrary code evaluation via Node `vm` in favor of audited bundled plugin declarations.
* **CRDT DoS Protection:** Implemented connection limits, 64KB update size caps, and per-minute rate limiting on collaborative WebSocket rooms.

---

## Performance

* **Database Query Indexing:** Retained low-latency indexed queries with compound indexes on `(publication_id, ...)` across all high-throughput tables.
* **What's New Memory Caching:** Implemented 1-hour in-memory cache for remote feed fetching with fallback resilience.

## Upgrade Notes

1. **Database Migration:** Execute migration `0026_multi_publication_tenant_isolation.sql` to populate `publication_id` columns with `pub_default`.
   ```bash
   pnpm db:migrate
   # Or for containerized deployment:
   docker compose -f compose.prod.yml run --rm migrate
   ```
2. **Container Update:** Pull and restart production containers:
   ```bash
   docker compose -f compose.prod.yml up -d --build
   ```
