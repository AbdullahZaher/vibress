# Vibress v1.0.0-GA Release Runbook

This document details the canonical procedure for cutting, verifying, and deploying the initial **v1.0.0-GA** release of Vibress.

---

## 1. Release Metadata

* **Release Tag:** `v1.0.0`
* **Release Name:** `Vibress v1.0.0-GA — General Availability`
* **Git Commit SHA:** `9f461d0aeae8c624c1c43fdfc439b861346df9eb`
* **Target Date:** 2026-09-13
* **Target Runtime:** Node.js 24 LTS, pnpm 11.22.0, PostgreSQL 16, Redis 7

---

## 2. Release Execution Steps

### Step 1: Pre-Release Verification
Run the complete regression suite on the release commit:
```bash
pnpm typecheck
pnpm -r lint
pnpm vitest run
pnpm build
```

### Step 2: Tag the Release
Create an annotated and signed Git tag:
```bash
git tag -a v1.0.0 -m "Vibress v1.0.0-GA — General Availability Release"
git push origin v1.0.0
```

### Step 3: Production Deployment
Execute the automated deployment pipeline on the production host:
```bash
./scripts/deploy-production.sh
```

### Step 4: Post-Release Verification
Run automated smoke tests and health checks:
```bash
pnpm production:verify
```

---

## 3. Post-Deployment Observation Schedule

| Checkpoint | Metrics to Inspect | Success Criteria |
| :--- | :--- | :--- |
| **T+0m** | Container statuses (`docker ps`), Gateway `/nginx-health` | All 7 containers `Up (healthy)` |
| **T+5m** | API error logs (`docker compose logs api`) | Zero 5xx responses |
| **T+15m** | Redis memory, PostgreSQL active pool connections | Pool usage < 30%, Redis memory < 50MB |
| **T+30m** | Worker outbox processing (`/worker-health/ready`) | Unprocessed outbox count = 0 |
| **T+1h** | Prometheus `/metrics` p95 response latencies | API p95 < 50ms, Search p95 < 15ms |
| **T+24h** | Daily automated backup verification | Backup snapshot created in `/backups` |
