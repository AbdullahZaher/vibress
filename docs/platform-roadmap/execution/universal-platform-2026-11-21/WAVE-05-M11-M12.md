# Wave 5 — Optional Cloud and Ecosystem (M11–M12)

**Current:** Existing Compose/Host plugin pieces are **reuse baseline only**; universal cloud control plane and marketplace milestones not independently implemented/certified. Preserve complete self-hosted product without any Vibress Cloud token or control-plane dependency.

**Entry:** prior Wave gates and code-first Framework release scope accepted. M11 and M12 are **optional product lines**, not blockers to the earlier Framework code-first GA unless marketed as part of that release. Run one complete test matrix at **the end of M11**, then another complete matrix at **the end of M12**, with separate independent A06 reviews and actual owner merge consent.


## M11 — 11 original Epics

- [ ] **M11-E01 — Cloud control plane** · `NOT_ACCEPTED` · A12/A04. **Implement:** separate optional cloud projects/installations/environments from self-hosted data planes. **Acceptance:** real app onboarding and revocation with isolated control-plane identity.
- [ ] **M11-E02 — Artifact build/deploy** · `NOT_ACCEPTED` · A04/A12. **Implement:** pinned signed image/build manifest, environment promotion and deploy metadata. **Acceptance:** same image digest staged across environments, rollback/forward-fix logs.
- [ ] **M11-E03 — Secrets and isolation** · `NOT_ACCEPTED` · A04/A05. **Implement:** independent per-install DB/Redis/S3/secret encryption and key rotation. **Acceptance:** A/B cross-app secret and data denial with actual credentials.
- [ ] **M11-E04 — Networking** · `NOT_ACCEPTED` · A04/A03. **Implement:** managed domains, TLS renewal, ingress auth, scoped preview routes. **Acceptance:** staging probes verify no cross-tenant headers, forged domains or unsafe admin access.
- [ ] **M11-E05 — Operations** · `NOT_ACCEPTED` · A04/A11. **Implement:** deployment metrics, alerts, backup schedules, incident and DR runbooks. **Acceptance:** observed health/SLI/SLO, fault recovery RPO/RTO and artifacts pinned.
- [ ] **M11-E06 — Cloud usage billing** · `NOT_ACCEPTED` · A12/A09. **Implement:** meter cloud-owned resource consumption with entitlement isolation. **Acceptance:** billing duplicate/retry and cross-tenant charge refusal.
- [ ] **M11-E07 — Deploy adapters** · `NOT_ACCEPTED` · A12/A04. **Implement:** portable Kubernetes/VM/Compose adapter with stable public configuration. **Acceptance:** deployed independent app remains usable if optional Cloud disabled.
- [ ] **M11-E08 — Deployment privileges / recovery** · `NOT_ACCEPTED` · A02/A04/A05. **Implement:** separate control plane deploy actor from installer and runtime; scoped backup. **Acceptance:** no cross-install DDL/backup and tested restore with issued role identities.
- [ ] **M11-E09 — Compatible promotion / forward-fix** · `NOT_ACCEPTED` · A04/A07. **Implement:** validate app and schema/event version skew and protected promotion. **Acceptance:** failure after upgrade uses recorded forward-fix, no claimed lossless downgrade.
- [ ] **M11-E10 — Tenant offboarding / data rights** · `NOT_ACCEPTED` · A04/A05. **Implement:** export/deletion ownership, residual backups and key expiry disclosure. **Acceptance:** tenant A export/delete never exposes B, retention windows auditable.
- [ ] **M11-E11 — Per-install infra and rollout isolation** · `NOT_ACCEPTED` · A04/A05/A03. **Implement:** actual service-specific A/B denials and rollout actor audience limits. **Acceptance:** DB, Redis/queue, S3, secret and backup negative matrix per installation.
