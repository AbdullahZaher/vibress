# PR #151 — Independent Architecture & Security Roadmap Review

> **Review date:** 2026-11-14. **Scope:** documentation and source-code inspection of the PR's proposed plan, selected host/Studio/plugin source, existing ADRs, Plugin Platform v3 and the 2026-11-13 security review. This is a **planning review**, not a penetration test, build verification, production certification or completed remediation. Changes proposed here update *documentation only*.

## Executive decision

**Recommendation: retain PR #151 as Draft, revise the plan, and do not approve implementation scope until the M00 decision gates below are accepted.** The strategy (a general app kernel alongside CMS and Studio, secure data generation, versioned modules, optional builder/AI/cloud) is sound as an *exploration*. It previously lacked precise deployment isolation, safe tenancy transaction contracts, migration privilege boundaries, an achievable v1 cut and falsifiable exit evidence. These are corrected in the linked specifications; runtime work is still outstanding.

### Status legend

All findings above are **review issues identified**. Their design corrections are or will be written in this PR; **none is a claim that production code, database migrations, security tests or deployments have been fixed**. Security severity is *planning risk prioritization*, not a tested CVSS finding.

## Highest-priority M00 decision gates

1. **ADR-PLAT-001:** v1 supported topology (recommended: application-per-installation), isolation units, DB/roles and data locality.
2. **ADR-PLAT-002:** application/tenant/principal/publication identity graph, trusted resolution and compatibility map.
3. **ADR-PLAT-003:** transaction-bound authorization and RLS implementation, service/maintenance bypass policy, realistic Postgres role design.
4. **ADR-PLAT-004:** Schema DSL trust tier, generated SQL ownership and migration approval/restore.
5. **ADR-PLAT-005:** API/compiler field/row policy and generated UI threat model.
6. **ADR-PLAT-006:** existing plugin SDK/ABI/version compatibility and trusted runtime boundary.
7. **ADR-PLAT-007:** minimum GA scope and explicit deferred features.
8. **ADR-PLAT-008:** release compatibility/rollback, measured RPO/RTO, evidence and stop/go authority.

See [decision gates](ARCHITECTURE-DECISION-GATES.md), [DB design](DATA-ISOLATION-AND-MIGRATIONS.md) and [v1 release cut](V1-SCOPE-AND-RELEASE-CRITERIA.md).
