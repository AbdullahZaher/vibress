# إعداد لغات الموقع في Vibress — دليل المالك

> **الحالة: سياسة معتمدة للتنفيذ، ولم تُطبّق برمجيًا بعد.** يشرح هذا الدليل السلوك المستهدف بعد إنجاز خطة التحديث، وليس وصفًا مضمونًا لكل شاشات النسخة الحالية. المرجع المعماري الملزم: [سياسة لغات Publication](../14-decisions/publication-language-policy.md)، والخطة الهندسية: [خطة التنفيذ](../development/LOCALIZATION_POLICY_IMPLEMENTATION_PLAN.md).

## 1. تحديد اللغة في التثبيت الأول (Onboarding)

يبدأ كل موقع **بلغة أساسية واحدة فقط**، ولا تُضاف الإنجليزية أو العربية تلقائيًا كلغة ثانية.

1. اختر **اللغة الأساسية**؛ مثل العربية أو الإنجليزية.
2. اترك **اللغات الإضافية** فارغة عندما تريد موقعًا أحادي اللغة.
3. فعّل لغة إضافية فقط إذا كنت ترغب بنشر محتوى مترجم إليها.
4. عند إنهاء التثبيت، تُحفظ اللغة الأساسية واللغات المفعّلة معًا، ولا تُشغّل الترجمة بالذكاء الاصطناعي تلقائيًا.

إذا كانت اللغة الأساسية **العربية**، فيجب عرض الموقع ولوحة الإدارة المدعومة بالكامل بالعربية، مع `RTL`. وإذا كانت **الإنجليزية**، فيجب عرضهما بالكامل بالإنجليزية، مع `LTR`. يشمل ذلك — عند اكتمال التنفيذ — الإعدادات وتسجيل الدخول والمحررات والتنبيهات ورسائل الخطأ. ولا تُعرض لغة أساسية جديدة بوصفها مدعومة بالكامل حتى يكتمل تعريب/ترجمة لوحة الإدارة إليها واختبارها؛ يمكن دعمها كلغة محتوى إضافية بصورة مستقلة.

## 2. إدارة اللغات من /admin/settings

يستطيع المالك أو المسؤول المخوّل، ضمن الموقع المسموح له، تنفيذ الآتي:

- الاطلاع على اللغة الأساسية واللغات الإضافية المفعّلة.
- تفعيل لغات جديدة دون إنشاء ترجمات تلقائية.
- تعطيل لغة إضافية بعد عرض أثر ذلك على الصفحات المنشورة وروابطها.
- طلب تغيير اللغة الأساسية مع فحص المحتوى الموجود أولًا؛ فلا يجوز تغيير وصف لغة المقالات القديمة دون إجراء انتقال واضح وآمن.

**تعطيل لغة لا يحذف الترجمات المخزنة.** تبقى البيانات محفوظة لإعادة التفعيل أو الصيانة المصرّح بها، بينما يتوقف ظهور المحتوى العام بتلك اللغة وفق قواعد النشر. وعند ترقية المواقع القائمة، يجب الحفاظ على الروابط المترجمة التي كانت متاحة للزوار حتى تسوية اللغات المفعّلة صراحةً، دون تعطيل مفاجئ.

## 3. متى تظهر صفحة Translation؟

| الإعداد | واجهة الإدارة والموقع الأساسي | صفحة Translation | مبدّل اللغة للزوار |
| --- | --- | --- | --- |
| الإنجليزية فقط | إنجليزية / LTR | مخفية | مخفي |
| العربية فقط | عربية / RTL | مخفية | مخفي |
| العربية أساسية + الإنجليزية | الإدارة والموقع الأساسي بالعربية | تظهر حسب الصلاحية | يظهر للنسخ المنشورة المتاحة |
| الإنجليزية أساسية + الفرنسية | الإدارة والموقع الأساسي بالإنجليزية | تظهر حسب الصلاحية | يظهر للنسخ المنشورة المتاحة |

لغة الموقع الأساسية تستخدم المسارات العامة **دون بادئة لغة**. لذلك قد يكون عنوان الصفحة العربية الأساسية `/posts/example`، لا `/ar/posts/example` بالضرورة. أما اللغات الإضافية فلها مساراتها المترجمة عند تفعيلها ونشر محتواها.

## 4. قواعد الترجمة والمراجعة

- الترجمة تتم من **لغة المقال الأصلية** إلى اللغة المستهدفة المختارة؛ ولا تُفترض الترجمة من الإنجليزية إلى العربية.
- لا تقبل أدوات الترجمة إنشاء نسخة للغة غير مفعّلة، أو ترجمة إلى لغة المقال نفسها.
- إظهار زر أو إخفاؤه ليس حماية أمنية كافية؛ يجب فرض الصلاحيات والعزل بين المواقع داخل API أيضًا.
- إضافة لغة لا تعني ترجمة المحتوى الموجود آليًا. وتبقى مسودات الذكاء الاصطناعي بحاجة إلى مراجعة وفق قواعد التحرير.
- لا يجوز عرض نص المقال الأصلي تحت عنوان أنه مترجم عندما لم تُترجم تفاصيل المحتوى بعد.
- لا يُعرض مقال بلغة أخرى كبديل صامت عند غياب الترجمة المنشورة المطلوبة.

## 5. احتياطات مهمة للمواقع الحالية

قبل تغيير لغة موقع يعمل بالفعل، راجع النسخ الاحتياطية والمقالات والصفحات والترجمات الموجودة والروابط المفهرسة وإعدادات القوالب والإضافات. تغيير اللغة الأساسية **لا يترجم المقالات القديمة** ولا يعيد تصنيف لغتها دون موافقة وإجراء انتقال منفصل. يجب أيضًا مراعاة `SEO` و`hreflang` و`sitemap` والتخزين المؤقت.

**حدود التنفيذ:** هذه السياسة معتمدة توثيقيًا فقط. لا تزال في النسخة الحالية افتراضات برمجية غير متوافقة معها، ولذلك لن تُوصف بأنها منفّذة أو مختبرة إنتاجيًا قبل إكمال التذاكر والاختبارات المذكورة في [خطة التنفيذ](../development/LOCALIZATION_POLICY_IMPLEMENTATION_PLAN.md).
